HireIQ Recruiter OS

Complete Technical & Cost Reference Manual

A comprehensive operations guide covering system flows, technical architecture, and free-tier processing capacity.

1. System Overview & Technology Stack

HireIQ Recruiter OS is an enterprise-grade AI-powered applicant tracking and screening system. It automates the end-to-end recruitment process: parsing job descriptions, parsing uploaded resumes, computing compatibility scores using a multi-factor hybrid heuristic engine, and running automated video interviews with real-time browser-based AI proctoring and automated transcription and analysis.

Layer / Component Technology Selected Operational Reason & Advantage

Backend API FastAPI (Python 3.10+) High-performance, async-native framework. Automatically generates OpenAPI/Swagger schemas.
Primary Database MongoDB Atlas (Cloud) Document database matching the highly nested, flexible structure of parsed candidate resumes and interview metrics.
Cloud Storage Supabase Storage (with Local Fallback) Primary provider for secure cloud storage of resume documents and interview audio recordings. Automatically falls back to local storage if keys are not configured.

2. Operating Cost Estimation & Free-Tier Capacity

HireIQ Recruiter OS is built to run on a "zero-dollar development & small business scale". By combining local open-source ML models with generous cloud developer limits, you do not pay anything for standard usage.

$0.00 / month

Provides free access to LLaMA-3.3-70b and Whisper models. Limits are rate-based: 100,000 requests per day (RPD) and 180,000 tokens per minute (TPM).

MongoDB Atlas (M0) Free Tier
$0.00 / month

Provides 512 MB of cloud storage. Adequate for storing thousands of parsed resumes, metadata structures, and interview records.

Supabase Storage Free Tier
$0.00 / month

Provides 1 GB of free storage. Adequate for thousands of resumes and audio files. Works seamlessly with zero-cost local folder fallback.

How Many Resumes Can I Parse Monthly Without Paying?

The primary limiting factor in the free stack is the MongoDB Atlas M0 Free Tier (512 MB storage). Let's calculate the exact capacity:

  • Average Candidate Document Size: 15 KB (includes raw text snippet, parsed fields, computed metrics, AI summary narrative, and activity logs).
  • Calculation: 512 MB * 1024 KB/MB / 15 KB = 34,952 Candidates.
  • Groq API Capacity: With a limit of 100,000 requests per day, the Groq API can handle 3,000,000 resume parses/chatbot operations per month.
Verdict: Free Processing Capacity
You can parse and store up to 25,000 - 30,000 resumes in your system without paying a single dollar. If you reach this limit, you can simply clean up old jobs/candidates to free up space or upgrade MongoDB Atlas (starting at $9/month).

4. Core System Flows (Step-by-Step)

  1. 1
    Authentication & Access Control Flow

    Secure onboarding and session management for recruiters.

    • Registration: Recruiter inputs name, email, and password. The password is hashed using bcrypt (with salt) and stored in the users collection.
    • Login: Recruiter submits credentials. The system compares the hashed password. Upon validation, a JWT token containing the user identity is generated using python-jose, signed with a secret key, and returned.
    • Session Management: The token is saved in the browser's localStorage. Axios request interceptors automatically append this JWT to the Authorization: Bearer <token> header on all backend requests.
  2. 2
    Job Creation & Parsing Flow

    Extracts requirements from plain job descriptions to construct scoring profiles.

    • Input: Recruiter types or pastes a job description in the frontend portal.
    • API Request: Triggers POST /jobs/create with the raw details.
    • LLM Extraction: The backend sends the text to the Groq LLaMA-3.3 model using a strict JSON format prompt. The LLM extracts: role, required skills, preferred skills, minimum experience, and required certifications.
    • Fast Fallback: If the Groq API key is missing or the request fails, a local keyword parser scans the text using precompiled regex models and RapidFuzz to map matches to the system's Master Skill Dictionary.
  3. 3
    Resume Upload & Parsing Cascade

    A hybrid approach combining local rule-based structures, cloud storage, and LLM validation to parse resumes.

    • Extraction: Resumes (PDF or Word) are uploaded. The raw text is extracted using PyPDF2 (PDFs) or mammoth (Word documents).
    • Local Cascade Rules: The local parser extracts metadata (e.g. Email via Regex, Name via Entity Extraction heuristics, Experience via date ranges in the work history).
    • Cloud Storage: The file is uploaded to Supabase Storage if credentials (`SUPABASE_URL` and `SUPABASE_SERVICE_KEY`) are set in the `.env` file. If they are missing, it falls back to saving files locally in `uploads/resumes/`.
    • LLM Validation: The text is packaged and sent to the Groq API. The LLM acts as a correction layer, extracting structural timelines, list of soft skills, projects, and certifications.
    • Vector Sync: The candidate document (including Supabase public URL or local upload file path) is saved to MongoDB. In parallel, the raw text is transformed into a 384-dimensional vector embedding using the local SentenceTransformer model and stored in the in-memory FAISS index.
  4. 4
    Weighted Scoring & Ranking Engine

    A deterministic math engine ranks candidates. Groq is never asked to compute the score (protecting against math inaccuracies and hallucinations).

    • Formula Composition: The total score is computed out of 100%:
      • Skills Match (40%): Compares candidate skills to job requirements using exact matching, alias mapping (e.g. JS -> JavaScript), and fast RapidFuzz Levenshtein matching.
      • Experience Match (25%): Evaluates years of experience compared to requirements.
      • Semantic Similarity (15%): Measures cosine distance between the job embedding and candidate resume embedding inside FAISS.
      • Projects & Certifications (15%): Checks for matching keywords in projects and certifications.
      • Quality Index (5%): Evaluates profile completeness.
    • Hard Penalties: Triggers deduction scores for major gaps (e.g. -20 points if >70% of required skills are missing; -10 points if total experience is less than half of the requirement).
  5. 5
    AI Narrative Feedback Generation

    Translates mathematical evaluation scores into human-readable recruiter notes.

    • Prompt Structuring: The backend formats a structured prompt containing the computed scores and key statistics, sending it to Groq LLaMA-3.3.
    • Output: Groq generates an executive summary, highlights core strengths, points out potential concerns or risks, and recommends hiring verdicts (Hire / Hold / Reject) matching the score thresholds.
  6. 6
    Recruiter Copilot (Chatbot) Flow

    A conversational interface to query candidate data.

    • Input: Recruiter asks a question (e.g. "Who has React experience and more than 5 years of work history?").
    • Intent Analysis: The backend parses the query to determine if the user is asking about candidates, general details, or job profiles.
    • Context Injection: The system fetches matching records from MongoDB and injects them into the LLM system prompt.
    • SSE Streaming: The backend streams responses in real-time from the Groq API to the frontend using Server-Sent Events (SSE) for a fluid chat experience.
  7. 7
    Interview Scheduling & Notification

    Automated coordination and room setup for video interviews.

    • Scheduling: The recruiter picks a date and time. The backend checks for timing conflicts.
    • LiveKit Room & Token: Calls `create_room` on LiveKit Cloud API. Generates a secure participant JWT token via `generate_recruiter_token` (room moderator status) and `generate_candidate_token` (restricted guest status).
    • Link Generation: A unique candidate join link is built: {FRONTEND_URL}/candidate-interview/{token}.
    • Email Dispatch: An SMTP routine sends invite emails to the candidate and recruiter. A background scheduler (APScheduler) queues a reminder email to be sent 15 minutes before the call.
  8. 8
    Interview Session & AI Proctoring Flow

    Protects interview integrity using local browser-based tracking and LiveKit components.

    • Token Verification: The candidate clicks the link, the frontend verifies the secure token, fetches the candidate JWT token, and connects natively to the LiveKit Cloud session using <LiveKitRoom>.
    • MediaPipe Proctoring: The candidate's camera feed is analyzed in the browser. MediaPipe FaceMesh calculates eye vector directions (tracking if the candidate looks away from the screen) and counts face presence.
    • Activity Tracking: JavaScript listeners track page visibility changes (tab switching) and clipboard copy-paste events. Violations are logged to the backend immediately.
    • Voice Detection: WebRTC Voice Activity Detection (VAD) monitors candidate voice levels to calculate speaking/listening ratios.
  9. 9
    Transcription & Automated Analysis Flow

    Generates a performance review report once the interview ends.

    • Speech-to-Text: Once the call completes, the recorded audio tracks are transmitted to Groq Whisper for transcription.
    • Heuristic Metric Compilation: The backend compiles metrics (e.g. eye contact percentage, speaking ratio, tab switch violations, filler word count).
    • Report Generation: The transcript and metrics are sent to Groq LLaMA-3.3 to compile a structured review card covering technical answers, communication skills, confidence, and cheating indicators.
    • PDF Builder: The database updates. A report template generates a downloadable, print-ready PDF using ReportLab.
